# Final Submission Checklist

- [ ] Moodle version, PHP version, database, OS, and local setup are recorded.
- [ ] Site and administration pages run without fatal errors.
- [ ] Exactly four synthetic test accounts exist: administrator, teacher, Student A, Student B.
- [ ] Teacher and both students are enrolled in one demonstration course with correct roles.
- [ ] Plugin installs through Site administration without Moodle core changes.
- [ ] Database table contains all required fields.
- [ ] `viewown`, `createrequest`, and `managecourserequests` capabilities are defined.
- [ ] Every protected entry point requires login.
- [ ] Student create/read/edit/delete rules work.
- [ ] Student A cannot access Student B's record by changing an ID.
- [ ] Teacher can filter and manage only an authorized course queue.
- [ ] AJAX/fetch update changes the page without a full reload.
- [ ] Every state change validates sesskey.
- [ ] Invalid status, empty fields, long fields, missing records, and XSS-style text are handled safely.
- [ ] No raw SQL concatenates user input.
- [ ] Mandatory test table has expected result, actual result, Pass/Fail, and evidence.
- [ ] Screenshots hide passwords, cookies, sesskeys, credentials, server paths, and private information.
- [ ] Report includes architecture, data model, authentication/session, access matrix, ownership, JSON, security, privacy, tests, checklist, reflection, limitations, and references.
- [ ] Clean-install test succeeds on the final plugin ZIP.
- [ ] Final ZIP contains only plugin source, README, report PDF, and selected screenshots.
- [ ] Final ZIP excludes Moodle core, `moodledata`, `config.php`, credentials, real passwords, sessions, cookies, caches, and unrelated personal data.
- [ ] Every team member can explain the code and demonstration.
